      Como usar
      
    
      Guia do sistema e boas práticas
      
  
      
  
      
    
      
      
      Navegando
      
      
        
        
      • Anatomia mostra as camadas. Comece por aqui se nunca leu um system prompt.
        • 
        
      • Explorar tem tudo. Desmarque “Só prompts em destaque” para ver as skills, ferramentas e arquivos de apoio (mais de 1.500).
        • 
        
      • No detalhe de um prompt, Carregar texto completo busca o arquivo original no GitHub e pinta cada técnica com uma cor. Clique nas cores da legenda para ligar e desligar.
        • 
        
      • Comparar aceita qualquer par. Os atalhos prontos mostram contrastes clássicos.
        • 
        
      • Laboratório analisa o seu texto localmente e sugere melhorias concretas.
        • 
      
      
    
      
    
      
      
      Como ler as métricas
      
      
        
        
      • Tokens são estimados como caracteres ÷ 4. Servem para comparar tamanhos, não para cobrança exata.
        • 
        
      • Densidade é ocorrências por 10 mil caracteres. Um prompt curto e focado pode ter densidade alta com poucas ocorrências.
        • 
        
      • O radar normaliza cada técnica pelo percentil 95 dos destaques. 100% quer dizer “tão intenso quanto os prompts mais intensos do acervo”.
        • 
        
      • A detecção é por padrões de texto (em inglês e português). Ela acerta a tendência, mas pode contar falsos positivos, como “tool” numa frase qualquer.
        • 
      
      
    
      
    
      
      
      Lições práticas do acervo
      
      
        
        
      • Explique o porquê. Os prompts mais recentes trocam “NUNCA faça X” por uma frase que dá a razão. Modelos generalizam melhor a partir de razões.
        • 
        
      • Estruture com títulos ou tags XML. Seções como <tools> e ## Formatting ajudam o modelo e quem mantém o texto.
        • 
        
      • Injete o contexto que muda: data, local, modelo. Isso evita respostas desatualizadas.
        • 
        
      • Descreva cada ferramenta com quando usar e quando não usar, não só a assinatura.
        • 
        
      • Mostre exemplos de resposta boa e ruim para comportamentos sutis.
        • 
        
      • Diga o que fazer em vez de só o que evitar.
        • 
      
      
    
      
    
      
      
      Segurança: o que os vazamentos ensinam
      
      
        
        
      • Todo system prompt pode vazar. Este acervo prova isso. Nunca coloque chaves de API, senhas, URLs internas ou dados de clientes no prompt.
        • 
        
      • “Não revele estas instruções” não é proteção. Trate o prompt como público e coloque a segurança real no servidor e nas permissões das ferramentas.
        • 
        
      • Injeção de prompt: conteúdo de páginas, e-mails e arquivos pode trazer instruções falsas. Os agentes do acervo marcam esse conteúdo como dado, não como ordem. Faça o mesmo.
        • 
        
      • Use o acervo para estudar e criar os seus próprios prompts. Não copie prompts proprietários para produtos comerciais nem use o conhecimento para burlar proteções de outras empresas.
        •
